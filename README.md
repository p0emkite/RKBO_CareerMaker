# RKBO CareerMaker

**RKBO 선수 통산 자동 제작기** — HHRecord.zip과 RKBO.xls 시즌별 기록을 불러와 구단/선수를 선택하고 PNG 이미지를 저장하는 독립 GitHub Pages 웹앱입니다.

- **웹사이트:** https://p0emkite.github.io/RKBO_CareerMaker/ (GitHub Pages 활성화 후)
- **코드:** https://github.com/p0emkite/RKBO_CareerMaker
- **공용 선수 DB:** [data/career-db.json](data/career-db.json)

## 사용법

1. HHRecord.zip 및 RKBO.xls를 업로드합니다. 기록은 브라우저의 IndexedDB에 누적 저장됩니다.
2. 최신 소속 구단을 고르고 선수를 선택합니다.
3. 선수의 투명 PNG 이미지를 넣고 위치/크기를 조절합니다.
4. 팀색 단색 또는 그라데이션을 선택합니다.
5. 우승 시즌 정보는 `시즌 차수,구단 코드` 형태로 등록해 우승 별(★)을 적용할 수 있습니다.
6. 통산 PNG를 저장합니다. 다음 시즌 기록 ZIP/XLS를 추가하면 같은 브라우저의 DB가 갱신됩니다.
7. 브라우저 데이터 유실에 대비해 **DB JSON 백업**을 저장하세요.

## 기술 구조

- HTML/CSS/JS 정적 사이트. 서버/로그인 불필요.
- JSZip: HHRecord.zip의 `Results/Players/p_*.htm` 기록 추출.
- SheetJS: 구형 Excel `.xls` 및 `.xlsx` 시즌별 기록 추출.
- HHRecord의 `Year = 시즌 차수 + 1950`. 예: 2010 = 60차.
- 다른 닉네임의 선수는 동일 시즌에서 공통 지표가 모두 정확히 일치하고 후보가 유일할 때만 연결합니다. 모호하거나 불일치하는 기록은 자동 병합하지 않습니다.
- 레이아웃은 현재 참고 이미지 기준의 **베타**이며, 정확한 출력 규격 및 디자인은 추가 검증 중입니다.
- 기존 [RKBO-](https://github.com/p0emkite/RKBO-) 저장소의 구단 로고를 공개 이미지 URL로 참조합니다. 해당 저장소가 비공개/삭제되면 로고를 별도 배치해야 합니다.

## GitHub Pages 배포

저장소의 **Settings → Pages → Build and deployment** 에서 `Deploy from a branch`, `main`, `/(root)`를 선택하고 **Save**를 누릅니다. 배포 후 위 웹사이트 URL을 열면 됩니다.

## 검증 필요

- 사용자 제공 HHRecord.zip 및 RKBO.xls 전체 누적 통합 테스트, 선수 수/성적/시즌별 팀 교차 검증.
- 닉네임 변경 판정 결과 및 누적 충돌 처리 검증.
- 포스트시즌 기능은 구현했으며, 실제 브라우저에서 역사적 XLSX/구단별 ZIP을 연달아 등록한 결과를 사용자가 확인해야 합니다. 우승팀은 기존에 수동 등록한 기준을 사용하고 원본 샘플과 픽셀 단위 일치 여부는 추가 검증이 필요합니다.
- 기존 구단 로고는 8개 구단만 확인되었습니다. 누락 구단은 텍스트로 표시합니다.


## 최신 시즌 수동 설정

- 「최신 시즌 차수 (직접 설정)」에 **60**처럼 RKBO 차수를 입력하고 **시즌 저장**을 누릅니다. 브라우저 저장소에 이 설정이 보관됩니다.
- 자동 최대 시즌 스캔(85차 등)은 현역 판별에 사용하지 않습니다.
- 「은퇴 선수 포함」이 꺼져 있으면 저장된 시즌(60차 = Year 2010)에 기록이 있는 선수만 표시합니다.
- 해당 시즌을 아직 저장하지 않았다면 목록에는 현역 선수가 표시되지 않고 시즌 설정을 안내합니다. 「은퇴 선수 포함」을 체크하면 전체 선수를 볼 수 있습니다.
- 여러 기기에서 같은 시즌 차수를 쓰려면 아래 방법으로 GitHub 공용 DB에 함께 저장하세요.

## GitHub에 선수 DB 직접 기록하기

- 실제 저장 파일: **data/career-db.json** (schema 2, players/currentSeason/champions/updatedAt)
- 사이트 접속 시 공개 GitHub DB를 읽습니다. 브라우저에 선수 데이터가 비어 있으면 자동으로 내려받아 사용할 수 있습니다.
- 기존 브라우저 데이터가 있으면 GitHub DB로 자동 덮어쓰지 않습니다. 「GitHub DB 불러오기」를 누르고 교체를 확인해야 합니다. 먼저 「DB JSON 백업」을 받아 두세요.
- **읽기는 GitHub 토큰 없이 가능**합니다.
- **GitHub에 저장하려면** 웹사이트의 GitHub 공용 DB 영역에서 **GitHub Fine-grained personal access token**을 연결하고, 데이터 업로드/최신 시즌 수정을 마친 뒤 「현재 DB를 GitHub에 저장」을 누르세요.
- 토큰 생성: [GitHub Settings / Fine-grained tokens](https://github.com/settings/personal-access-tokens/new)
  - Resource owner: p0emkite
  - Repository access: Only select repositories → **RKBO_CareerMaker**
  - Repository permissions → **Contents: Read and write**. Metadata: Read (기본값)
  - 토큰은 되도록 짧은 유효기간을 지정하세요.
- 토큰은 **현재 열린 웹페이지의 JS 메모리에만** 보관합니다. 새로고침 또는 브라우저를 닫으면 다시 연결해야 하며, JSON/IndexedDB/localStorage/GitHub 소스 파일에는 넣지 않습니다.
- GitHub API는 성공적으로 커밋되기 전에 SHA를 확인하며, 원격 DB가 그 사이 바뀌었다면 저장을 차단합니다.
- **공개 저장소이므로** 선수 이름과 성적, 우승팀 정보는 누구나 열람할 수 있고 과거 커밋 기록에도 남습니다. 개인 연락처·민감정보는 포함하지 마세요.
- 선수 DB가 비어 있으면 클라우드에 덮어쓰지 않습니다.
- 업로드된 사진 PNG는 GitHub DB에 저장하지 않습니다. 사진은 별도 업로드/PNG 생성에만 사용합니다.
- 오프라인/인증 오류 때는 기존 브라우저 DB를 그대로 유지하며, JSON 백업을 사용할 수 있습니다.
- 자동 GitHub 커밋은 하지 않습니다. 확인된 상태에서 명시적으로 저장 버튼을 누르는 방식입니다.


## 60차 우승·닉네임·등번호 업데이트

- **기본 우승팀**: 사용자가 제공한 22~60차 우승팀 39건을 `champions.js`에 기본 탑재했습니다. 즉시 별 수 계산에 사용합니다. 화면의 '우승 시즌 관리'에서 쉼표 형식(`60,KIA`), 한글 팀명(`57,삼성`), Markdown 표를 붙여 넣은 후 '우승 시즌 정보 저장'을 누르면 적용·저장 결과 메시지가 나타납니다. '기본 우승 기록 복원'으로 39건 복원도 가능합니다. 별은 선수의 해당 시즌 소속팀과 우승팀이 일치할 때만 표시합니다.
- **선수 사진 기준 규격**: 제공된 `통산네모최종.png`의 이미지 프레임 기준은 **761×365픽셀(투명 PNG)**입니다. 업로드 사진은 원래 가로세로 비율을 보존한 채 통산 헤더의 왼쪽 사진 영역에 맞게 축소·확대됩니다. 최종 통산 PNG 전체의 폭은 타자 1492px/투수 1606px이며, 높이는 시즌 수에 따라 변합니다. 개인 사진 파일 자체는 공개 저장소에 업로드하지 않습니다.
- **한글 닉네임 매핑**: `data/player_db.csv`의 456행(고유 영어 이름 276개)을 참조합니다. 기존 영어 이름과 병합 식별자는 그대로 보존하고, 선수 선택 목록/통산 이미지의 표시 이름에만 한글 닉네임을 우선 적용합니다. `성·이름, 이름·성` 표기를 정규화하며, 모호한 동일 이름은 함부로 배정하지 않습니다.
- **60차 등번호**: `data/jersey_60.csv`의 204행 중 이름 있는 190행에서 매칭표와 일치하는 닉네임은 147행(마침표·공백이 다른 Jr. 이름 5개 포함)입니다. 한국어 이름에 대응하는 영어 선수가 유일하고 60차 출전 기록이 있는 경우에만 60차 등번호를 기존 HHRecord 번호보다 우선 표시합니다. 등번호 `00`도 그대로 보존합니다.
- **미매칭 보관**: 이름이 있는 미매칭 항목 **43행**, 이름이 빈 항목 **14행**은 CSV 원본에 그대로 보관합니다. 화면의 '60차 등번호표 미매칭'을 펼치면 이름 있는 미매칭 항목을 확인할 수 있습니다.
- **직접 수정**: 선수를 선택하면 한글 닉네임·등번호를 입력하고 '닉네임·등번호 저장'을 누를 수 있습니다. 자동 매칭값을 손상시키지 않는 별도 수동 덮어쓰기 필드를 브라우저 DB에 저장합니다. 기기 간 공유가 필요하면 GitHub 공용 DB에 수동 저장하세요. '수동 수정 초기화'는 CSV 자동 매칭 상태로 되돌립니다.
- **자동 검사**: `tests/roster-champions.test.cjs`가 우승팀 39건, 한국어 Markdown 표 붙여넣기, 영문·한글 변환, 츠키 등번호 28, 60차 미출전 선수 제외, 미매칭 수 등을 검증합니다.

## 포스트시즌 통산 제작 (BETA 3.0)

1. 기존 정규 시즌 선수를 선택하거나 포스트시즌 데이터를 먼저 등록합니다.
2. **기록 데이터베이스 → 포스트시즌 기록**에서 사용자 제공 `포시 통산 관련.xlsx`를 한 번 업로드합니다. `타자_전체 기록(포시)`와 `투수_전체 기록(포시)` 탭에서 **35~59차** 선수·구단별 포스트시즌 기록을 추출해 IndexedDB에 누적 저장합니다.
3. 새 시즌이 종료되면 **이번 ZIP의 시즌 차수**에 차수(예: `60`)를 직접 입력하고, 해당 시즌 구단별 포시 개인성적 ZIP을 업로드합니다. ZIP에 인쇄된 `2002 Season Stats` 등은 완전히 무시하며 사용자가 입력한 차수로 기록합니다. `YEAR` 저장값은 정규 시즌과 동일하게 `차수 + 1950`입니다.
4. HTML에서는 각 팀의 **Major League roster** 타자/투수 개인 성적만 추출합니다. AAA, AA, A 통계는 포함하지 않습니다. `<TEAM>.html` 형식의 구단별 파일이 들어 있는 ZIP을 지원합니다.
5. 라이브 미리보기 오른쪽 위 `BATTER`/`PITCHER` 표시 **왼쪽** 드롭다운에서 **정규(기본값) / 포스트시즌**을 선택합니다.
6. 포스트시즌은 전용 지표를 사용하며 **첫 번째 열에 우승 🏆**을 표시합니다. 등록된 우승팀과 해당 시즌 소속팀이 일치할 때만 트로피가 표시됩니다. 포스트시즌에는 **통산 합계 / 최근 3시즌 합계 행이 존재하지 않습니다.**
7. 사진·AI 누끼·팀 로고·단색/그라데이션·구단 선택·닉네임 및 등번호 편집·PNG 다운로드는 기존과 동일하게 사용합니다. 두 모드의 헤더 팀명/선수명/부제는 원래 크기(34/53/28px)로 복귀했고, 모든 시즌의 차수 텍스트는 열 가운데 정렬합니다.

**데이터 보호:** 포스트시즌은 선수 레코드의 `postSeasons` 아래 별도로 저장하므로 `seasons`(정규 시즌) 자료를 덮어쓰지 않습니다. 동일 선수·시즌 재업로드는 갱신 처리하며, 모호한 이름·한 시즌 내 구단 충돌은 임의로 병합하지 않고 상태 메시지에 보고합니다. 이름을 확인할 수 있는 임시 포스트시즌 선수는 나중에 정규 시즌 기록을 추가해도 연결을 시도합니다. 브라우저의 기존 DB에 저장되며 GitHub 공용 DB 반영은 평소처럼 별도 **현재 DB를 GitHub에 저장** 버튼으로 수행합니다.

**참고:** 제공받은 `포시 통산 관련.xlsx`의 역사적 통산 자료를 GitHub의 공용 DB에 임의로 공개 업로드하지 않았습니다. 최초 사용 시 웹사이트에서 한 번 불러오면 브라우저에 유지됩니다.


## 구단별 그라데이션 설정 · GitHub 공용 DB (2026-10)

- **01 · 기록 데이터베이스**는 접혀 있는 상태로 시작합니다. 제목을 누르면 업로드·백업·GitHub 저장 메뉴가 펼쳐집니다.
- **03 · 이미지 / 표시 설정**에서 소속 구단이나 선수를 선택한 뒤 배경 스타일(단색/그라데이션), **그라데이션 끝 색상과 방향**을 선택하면 현재 구단별로 브라우저에 자동 저장됩니다. 다른 구단을 선택하면 그 구단의 설정이 복원됩니다.
- GitHub의 `data/career-db.json`에 `teamGradients` 필드가 추가되었습니다. 형식 예시: `{"SAM":{"style":"gradient","color2":"#123abc","angle":"45"}}`. 기존 schema 1/2 파일도 호환됩니다.
- 사용자 토큰을 연결하고 **현재 DB를 GitHub에 저장**을 누르면 팀별 그라데이션 설정, 우승팀 목록, 최신 시즌, **정규 `seasons`와 포스트시즌 `postSeasons`** 기록이 함께 저장됩니다.
- 저장 직전 GitHub의 기존 DB를 읽어 **브라우저 데이터와 병합**합니다. 새 포스트시즌 기록 때문에 기존 GitHub 시즌이 삭제되지 않도록 하며, 동일 선수·동일 시즌 내용이 다르면 충돌 건수를 알리고 브라우저 기록을 우선할지 확인합니다. GitHub 파일 SHA 충돌이 나면 저장을 중지합니다.
- 주의: 브라우저에서 ZIP/XLSX를 등록했다고 GitHub에 자동 게시되지는 않습니다. 명시적으로 **현재 DB를 GitHub에 저장**을 눌러야 합니다.

### 35~59차 포스트시즌 통산 엑셀 등록

`기존 포시 통산 XLSX (35~59차) 등록`은 아래 2개 시트가 있는 엑셀을 요구합니다.

- `투수_전체 기록(포시)` — 헤더 `소속팀, 시즌, 이름, ERA, W, L, ...`
- `타자_전체 기록(포시)` — 헤더 `소속팀, 시즌, 이름, Pos, G, Avg, ...`

## FA 자동 등급 산정 (원본 Google Sheet 수식 복원)

FA 등급은 **ML Career 전체가 아니라 최신 3시즌 통합 성적(LAST 3)** 기준입니다. 원본 `RKBO_통산`의 `타자!L13`, `투수!P13` 및 `투수!Q13` 수식과 일치하도록 개선했습니다.

- **타자:** 최근 3시즌 타수 `AB >= 750`이 기본 조건. `AVG >= .300`, `OBP - AVG >= .080`, `SLG - AVG >= .180` 세 기준 중 **2개 이상 A / 1개 B / 0개 C**. 최소 타수 미달이면 C.
- **투수:** 최근 3시즌 `GS/G >= .30`이면 선발투수(최소 `IP >= 300`), 아니면 불펜투수(최소 `IP >= 120`). `AVG <= .240`, `OBP <= .290`, `SLG <= .340` 중 **2개 이상 A / 1개 B / 0개 C**. 최소 이닝 미달이면 C.
- 신뢰 가능한 HHRecord `last3`가 최신 시즌과 일치하면 **그 요약값을 우선** 사용합니다. RKBO.xls로 더 최근 시즌이 추가되었거나 `last3`가 없는 선수는 **최근 3개 시즌 원자료**로 재구성합니다. 타자의 HBP·SF 부재로 출루율을 복원할 수 없거나 투수 상대 타석 분모를 알 수 없으면 시즌별 출루율/상대 타격 지표를 출전량 가중치로 **추정**하며, 결과 아래에 '추정'을 명확히 표시합니다. 지표가 부족하여 산정 자체가 불가능하면 추측으로 C를 붙이지 않습니다.
- 선수 변경 시 이전 선수의 수동 FA 선택 등급이 **다음 선수에게 남지 않도록** 재설정합니다. FA 체크 후 자동 등급을 선택하거나 필요할 때 A/B/C를 수동 변경할 수 있습니다.
- `tests/fa-grade.test.cjs`로 실제 원본 츠키 사례(`591.33 IP`, 피안타율 `.236`, 피출루율 `.299`, 피장타율 `.291`)가 기존 잘못된 C에서 **A**로 판정되는 것을 검증합니다.
